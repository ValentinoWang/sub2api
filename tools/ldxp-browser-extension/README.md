# 小铺补货助手

Chrome Manifest V3 扩展。小铺登录只在 `https://www.ldxp.cn` 的当前商户标签页使用；扩展后台只保存本站补货设备凭据。Chrome 在线、有已登录商户标签页、且已点击「保存并自动补货」时，每分钟检查一次授权商品库存。

## 项目内的配置位置

本插件按个人自用维护，统一入口为：

`/Users/vsiyo/Desktop/Opensource_Tool/Sub2api/tools/ldxp-browser-extension`

| 配置或资料 | 保存位置 | 使用方式 |
| --- | --- | --- |
| 两个站点的地址、名称、补货管理入口 | 本目录 `config.js` | 页面和后台从同一配置读取；地址受 `manifest.json` 权限约束 |
| 插件安装入口 | 本目录 `manifest.json` | Chrome 加载已解压的扩展程序时选择本目录 |
| 两站各自的商品 ID、面额 | 各站补货管理 | 用下表入口配置；扩展通过设备授权读取，不在文件中复制商品映射 |
| 每种额度的未售库存目标 | 插件「自动维持库存」页面；默认值在 `config.js` | 默认 999 张，一次应用到全部选中商品，并保存至对应站点后端 |
| 两站各自的补货设备凭据 | 当前 Chrome 扩展存储 | 首次分别填写一次，保存后可留空复用；真实密钥不写入源码或 ZIP |
| 完整操作与更新说明 | 本目录 `README.md`、插件设置页 | 插件前端直接显示步骤与入口 |

| 站点 | 补货管理入口 |
| --- | --- |
| 本地测试商品 | http://127.0.0.1:8080/admin/tools/ldxp |
| 生产正式商品 | https://ai.rest2build.lol/admin/tools/ldxp |

无需维护桌面源码副本。如果以前从桌面加载了插件，更换加载目录可能生成另一个扩展身份，Chrome 不会自动迁移已有凭据或绑定。先暂停旧扩展，再在项目目录这份插件中重新保存两站绑定。后续直接修改项目代码，并在 Chrome 扩展管理页重新加载即可。

## 安装和绑定

1. 个人自用直接使用上述项目目录。需要便携副本时，也可从站点管理页下载 `/assets/ldxp-browser-extension.zip` 并解压。
2. 打开 `chrome://extensions`，启用开发者模式，点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的文件夹。
3. 在每个站点的 Chrome 补货管理中创建设备，选择「全部已启用商品」。分别复制一次性显示的补货设备凭据。新增商品后如当前设备没有该商品权限，需在对应站点创建包含新商品的设备；扩展不能自行扩大设备授权。
4. 在同一 Chrome 打开 `https://www.ldxp.cn/merchant/goods/list?is_proxy=0` 并登录。
5. 点击 Chrome 工具栏的小铺补货助手图标，直接打开唯一的「自动维持库存」页面。两站首次各填写一次补货设备凭据，点击「读取两个站点的商品」；已启用、已授权且未冲突的额度默认全选。也可只读取一个站点或取消不需要的额度。
6. 「每种额度保持的未售库存」默认 **999 张**。点击一次「保存并自动补货」，插件会配对全部选中商品、向两站分别保存目标、核对库存并开始分批补足。以后凭据留空即可复用，不用逐个额度检查和开始。
7. 看「库存与运行状态」：每个商品显示当前库存 / 目标，未满时显示「正在补足库存」，到达目标后显示「自动维持中」。需要停止时点击「暂停全部」。

首次补满 999 张需要多轮：每轮最多补服务端配置的批次数量（上限 20 张），之后每分钟检查并补下一批。例如现有 998 张就补 1 张，999 张不补，售出 2 张后补 2 张。不会为了改小目标而删除已有库存。浏览器在线并有登录中的商户页才可持续检查，关机、休眠、断网或登录失效期间无法保证商品不断货。

暂停后，重新登录或联网不会自行恢复。排除下方暂停原因后，再点「保存并自动补货」统一重新核验并恢复。未核实的上传批次须先完成库存核对，不能跳过。全局开关关闭、设备被撤销或服务端冻结时，需在对应站点补货管理中处理。

## 配对与保存规则

- 商品目录来自对应站点的设备授权，不能根据标题或面额猜测商品 ID；本地商品只生成本地码，正式商品只生成正式码。同一小铺商品不能绑定两个站点或设备。
- 默认全选可绑定额度；取消勾选不会删除或暂停旧绑定。需要停止所有已有商品时使用「暂停全部」。
- 两站的设备与商品身份全部通过核对后，才一次写入扩展绑定和凭据；身份核对失败不会保存部分新绑定。重复保存同一绑定保留库存记录和待核实批次。
- 库存目标随后分别写入两站，再逐项核验并启动。两站请求并非跨站事务：一个站点失败只暂停该站选中商品，另一个可继续；页面明确显示实际启动数量和失败原因。目标只有获得该站后端确认后才显示在商品状态中。
- 需要后端支持 `POST /api/v1/ldxp/device/stock-target`。旧后端会显示更新提示并暂停，不会假装已启用。更新插件源码或 ZIP 不会自动更新本地或生产后端；两站须分别运行支持此功能的版本，生产更新须单独确认。
- 库存目标仅可设置 1–999 张；设备只能改已授权商品的目标，不能改商品、额度、批次数量或管理员总开关。有待核实批次时不能降低该商品目标。
- 老版本绑定的凭据仅在该站点有唯一设备凭据时自动复用。存在多个不同凭据时，请填写要使用的凭据，不会猜测或使用另一站凭据。
- 更新项目文件后，在 Chrome 扩展管理页重新加载，再重新打开设置页。扩展存储属于浏览器，不在安装目录里；不要卸载扩展或清除其存储。

## 库存与中断规则

- 读取小铺 `auth-token` 的精确 `{value,expiry}` 结构，仅在小铺页面的 MAIN world 中作为 `Merchant-Token` 使用。这个值不离开小铺页面，不发送给本站，也不存入扩展配置。
- 仅固定商户库存与上传接口可以被调用。库存读取 `data.list[].secret` 和 `id`，分页完整后再做一次完整扫描。总数变化、重复 ID/摘要、空白/多行码、缺字段、非成功响应均拒绝放行。发送本站的旧库存只有 SHA-256 摘要，没有旧卡密码明文。
- 领取的本站批次校验商品和逐码摘要，明文仅用于这次上传，不写入扩展持久存储。上传开始前，先持久化原批次与不确定状态，再请求服务端锁定；本地保留原批次编号与摘要，恢复核验时提交原批次编号。即使开始或上传响应丢失，也只能核验原批次，绝不盲重传或领取新批。
- 小铺上传返回成功并不等于完成。只有上传后重新全量逐码核验并获本站确认，才能清除原批次并继续。如果服务端已经逐码核验完成但响应丢失，后续核验按设备、商品和原批次编号查询已完成状态；即使其中卡密后来售出，也能恢复。未曾核验完成的部分上传或售出情况仍保持不确定，等待管理员处理。
- `chrome.alarms` 唤醒 service worker；任务采用单 worker 互斥和持久状态标记。没有 `setInterval` 或常驻后台要求。工作中点击暂停，会在下一个副作用前停止；已开始的上传仍需完成库存核验。

## 权限和范围

默认仅授权 `https://www.ldxp.cn/*`；保存站点时按需申请 `https://ai.rest2build.lol/*` 或本机 `http://127.0.0.1/*`。Chrome host match pattern 本身不能限定端口，因此本机权限模式覆盖 localhost 端口，但实际后端请求代码严格只允许 `http://127.0.0.1:8080`。不接受任意 URL，不使用 cookies、webRequest、all_urls、外部消息或可供网页调用的桥。

配置存于扩展 `storage.local`，权限设为 `TRUSTED_CONTEXTS`，不使用 sync。只有自身 options 设置页的同扩展消息可以访问后台命令；网页既不能读取设备凭据，也不能借后台调用本站。站点、固定 LDXP 配置、设备、商品共同组成持久状态键。设备凭据必须匹配 `ldxpd_` 格式，服务端再验证授权范围，管理员凭据不能使用。

## 开发与打包

```sh
node --test tools/ldxp-browser-extension/test/*.test.js
node tools/ldxp-browser-extension/package.mjs
```

打包脚本不需要第三方运行时依赖、zip 或 Python；固定时间戳、声明的运行文件白名单和 CRC32 生成可复现 ZIP。默认输出 `frontend/public/assets/ldxp-browser-extension.zip`，也可将输出路径作为第一个参数。生成 ZIP 不提交 Git。前端构建应先运行打包脚本，Docker 构建需把 `tools/ldxp-browser-extension` 复制到构建阶段的相应位置。

界面单元测试复用 frontend 的 jsdom 开发依赖，请先完成 `pnpm --dir frontend install --frozen-lockfile`。
