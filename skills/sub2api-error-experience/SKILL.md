# 错误经验：先让 Codex 接手

产出不是只有人能读的复盘文章，而是一份能直接发给新 Codex 任务的排障入口。项目栏目名为“错误经验”，副标题为“解决你使用codex或者claudecode的最后一公里”。

## 读者：中转站使用者

这是面向本站其他使用者的公开排障帮助，不是作者与 Codex 的对话日志或内部开发复盘。使用“你遇到什么、如何处理、如何确认恢复”的视角，默认读者只有自己的客户端、本站接入地址与个人 API Key，没有服务器、Docker 或管理员权限。

- 不展示聊天原话、私人验收反馈、对话时间线、作者的任务进展、内部操作流水账或私有 provider 命名。内容日期用于说明文章更新与版本适用性，不记录某个人何时回复。
- 历史案例只保留能解释问题的症状、版本差异、根因与脱敏验证结果。内部操作失误转写为读者需要的注意事项，不复述执行者的行为过程。
- 写充分的帮助内容：如何判断是否同类问题、各排查项为什么相关、结果分别意味着什么、处理前提与风险、恢复后的检查、未解决时联系谁及提供什么。不是增加泛泛原则或重复摘要凑篇幅。
- 完整提示词以读者自己的环境为对象，不假定其已经升级 CLI、拥有本地服务或已证实 API 可用；未知信息先检查。普通使用者不得被引导 SSH 登录、重建中转站、修改服务账号或访问他人凭证。
- “给人看的”部分按问题组织实用解释，不强套项目背景、对话脉络、阶段成果等开发日记结构。HTML 与 Markdown 都提供完整内容，不把 HTML 只做成内部复盘的摘要。

## 登记单位：一个完整问题

一个可识别的完整故障就是一个可复用的错误经验模块，对应一个编号、一张入口卡片和一份完整案例文档。复用的是整套问题识别、排查、处理与验收过程，不是拆散后的知识点。

例如，“GPT-6 已接入，为什么 Codex 仍然看不见？”整体登记为 ERR-001。桌面内置版本、模型目录、provider、缓存、升级接续等属于这个模块内部的排查内容，不分别登记为同级经验卡片，不单独统计数量，也不各自重复生成提示词。

只有另一个具有独立症状与处理目标的完整问题，才新增模块。列表卡片按完整问题命名，时间与状态属于该问题；卡片展开或进入详情后仍保持同一个模块的上下文。

## 必须遵守的阅读顺序

每个完整问题模块、对应的 Markdown 详情和 HTML 经验卡片均按以下三个部分排列。标题、日期和状态可以前置，但根因长文、证据表和背景讨论不得抢占前两部分。

### 1. 情况说明

用用户能识别的语言写出具体症状、出现位置、预期与实际差异，帮助读者判断自己是否遇到同类问题。把“已确认事实”和“怀疑”分开，不用复盘结论冒充当时已知条件。

### 2. Codex 帮你处理

提供完整、自包含、可直接发送给 Codex 的提示词，放在独立 text 代码块中；HTML 提供相同文本及“复制提示词”命令。提示词不能只说“处理上面的问题”“按本文操作”，必须脱离本文和原对话仍能执行。

提示词至少说明：

- 我看到的症状，以及希望恢复的用户行为。
- 已知客户端/系统环境；未知信息让 Codex 先检查，不填入本案例作者的路径、主机或账号作为别人的默认值。
- 从实际执行入口、配置到服务响应的必要检查。使用现有证据缩小范围，不预设所有用户都与历史案例根因相同。
- 行动范围：先诊断；仅执行提示词明确允许且可恢复的局部修改。生产中断、批量删除、账号/密钥变更及发布不是“帮我修复”的默认扩展权限。
- 可观察的验收标准、未通过时需要报告的证据与下一步。明确“API 成功”“客户端可见”“实际选中”“长会话正常”是不同结果。

提示词不得包含密钥、认证头、私有会话内容。目录检查与真实生成的费用区别有意义时说明范围，不把无限重试写成默认策略。因工具、登录或权限缺失而无法完成时，要求报告具体阻塞，不虚构成功。

### 3. 给人看的：原因、证据与经验

最后解释：症状为何发生、做了什么、以什么证据判定结果、哪些没有验证、下次如何减少同类问题。内部排查要点使用段落、列表或表格，不再拆成独立错误经验卡片。可用折叠详情降低首屏阅读负担。

这个第三部分优先解释具体原因、处理步骤、常见误区、自查结果与求助信息；所有内容服务于读者解决这个完整问题，不让内部复盘模板覆盖用户要求的前三段顺序。

## 时间与证据

- 每条案例包含稳定编号、标题、适用客户端及实际记录或更新时间；状态只描述案例或文章适用性，不展示私人验收反馈。
- 写入时间用执行时的真实时钟，对读者显示文章日期即可。不要估算故障时长。
- 标明历史观测、文档来源与尚未验证的区别，不附聊天引语作为公开证据。历史版本要注明对应日期，不作为未来最低版本的永久规则。
- 没有做 Claude Code 测试就写“通用方法可迁移，Claude Code 未专项验证”。不将 Codex 的命令和目录硬套到 Claude Code。
- 不将一个历史案例的成功写成所有用户、所有客户端或当前站点状态的保证；不将建议的操作写成已实施的自动门禁。

## 项目落盘与预览

本 Skill 在 Sub2API 项目中的源目录为 `skills/sub2api-error-experience/`；项目发现入口为 `.agents/skills/sub2api-error-experience`。

- 案例和索引保存在项目 `docs/error-experiences/`。优先沿用同目录现有案例与 HTML 风格，只读需要的部分。
- Markdown 保存完整案例，`index.html` 保存可直接打开的卡片预览。两者的事实与可复制提示词保持一致。
- 新建卡片自带“情况说明 → Codex 帮你处理 → 给人看的”顺序，提供时间和状态。复制失败必须明确反馈，可回退到选中文本，不能伪报复制成功。
- 本地静态预览不等于生产发布。用户只要求预览时不要自行加入生产路由、部署、提交或推送。
- 修改 HTML 后检查桌面/手机布局、提示词复制或回退、卡片筛选及本地资源加载，给用户绝对路径 HTML 链接。
- 普通经验归档不自动成为 SSOT，不写入全局 memories 或 Obsidian，除非用户另行要求。
