# Codex 本地记忆统一工具待拍板问题

## 当前状态

截至 2026-07-23，第一版本地工具没有未拍板产品问题。稳定编号保留，不重新编号。

## 已拍板决定

- `OP-01`：第一版同时支持 macOS、Windows、Linux。
- `OP-02`：站内公开 Docs 固定为 `/docs` 与 `/docs/codex-memory`，无需登录并可从未登录首屏或全局导航发现；`/Api_subscribe` 保持管理员权限。
- `OP-03`：只统一同一台电脑上的本地 Codex 状态，不导入服务端历史。
- `OP-04`：脚本提醒用户后，自动设置统一的 `CODEX_HOME` 并迁移全部可迁移状态；凭据始终排除，`config.toml` 不得整体替换。
- `OP-05`：第一版以方便 Codex 调用的脚本/命令行工具交付。
- `OP-06`：GitHub Releases 保存不可变制品、校验文件和发布清单；Sub2API Docs 读取同一清单。
- `OP-07`：Codex Memory 的功能代码和通用文档源文件共同保存在本项目团队维护的 Sub2API fork 仓库中。网站 `/docs/codex-memory` 渲染该文档，并组合当前部署提供的域名、下载镜像、支持渠道和发布版本等实例信息。原始 Sub2API 父仓库不是当前依赖；只有未来提交并获其接受时才关联。
- `OP-08`：属于现有 Sub2API 服务端 Responses 连续性配置，与本地工具无关；保持默认关闭/按 API 密钥灰度，本项目不修改、不阻塞。
- `OP-09`：内容不同的任务均保留并标注来源；仅当任务身份与内容摘要同时一致时去重；不自动覆盖。
- `OP-10`：多账户本地状态合并前自动创建一次本地备份；默认不删除或覆盖来源数据，只生成合并结果；用户确认结果后才可主动覆盖或清理；提供恢复命令。第一版不做自动过期、配额、审计或服务端留存政策。

## OP-10 合并与恢复合同

```text
账户 A 本地状态 + 账户 B 本地状态
            -> 生成合并预览
            -> 识别重复项与冲突项
            -> 展示来源和保留策略
            -> 自动创建本地备份
            -> 用户明确确认
            -> 写入独立合并结果
            -> 回读验证或执行恢复命令
```

冲突处理继续遵守 OP-09：完全相同的任务身份和摘要才能去重；差异内容默认均保留并标注来源。记忆类型可以分类展示，但第一版不依据“最近一次”或推断的场景自动覆盖用户偏好、事实或历史对话。

Redis、PostgreSQL、服务端配额、导出、删除、审计和长期留存只属于未来可能的服务端托管设计备注，不是当前版本的产品问题、实施范围或阻塞项。
