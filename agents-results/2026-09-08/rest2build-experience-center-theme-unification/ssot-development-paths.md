# 经验中心与统一主题：开发 SSOT

## 业务结论与范围

用户明确要求开发 SSOT。经验中心、P1 接入帮助、首页定位和公共深色导航需要在后续实现中一起收束，并以本地热更新预览（HMR）的桌面和移动视觉行为独立验收；本轮只交付开发路径，不修改产品源码、不部署或同步生产。

现有经验页是单列卡片，公共页面容器被最大宽度样式（`max-w-3xl`）限制，P1 接入弹窗与首页形成不同的视觉语言。目标不是单独美化一个列表，而是建立一个公共的经验入口：用户可先从主题理解问题，再进入具体经验；P1 中的接入帮助只显示与当前场景相关的主题入口；首页和公共页采用同一组版式、间距、边框和深色层级。

本 SSOT 的最高证据级别为本地运行层级（`local-runtime`）。它只授权本地开发服务器（Vite）的热更新预览（HMR），并通过只读代理查看公开页面。它不授权登录远端、创建或修改数据、同步服务器、生产构建、后端语言测试（Go）、容器构建（Docker）、发布、支付、兑换、密钥管理或任何生产结论。

## 产品与交互合同

### 经验中心信息架构

经验中心路由（`/experiences`）是公开的经验中心，而非把所有文章并排堆放的列表。页面首屏包含标题、短说明和主题目录；默认主题为“全部”，主题状态与分类查询参数（`category`）同步。第一版主题固定为以下四组，主题名可在实现时润色，但标识和语义必须稳定：

| 主题标识 | 页面可见名称 | 内容范围 | P1 关联方式 |
| --- | --- | --- | --- |
| `setup` | 接入配置 | Codex、Claude Code、OpenAI 兼容接入与本地配置。 | 当用户在 P1 选择客户端或环境时显示。 |
| `continuity` | 对话接续 | 切换接入后旧任务无法继续、配置变更和恢复边界。 | 当 P1 说明 provider、配置或旧会话问题时显示。 |
| `models-usage` | 模型与用量 | 模型可见性、模型选择、额度和用量解释。 | 当 P1 指向模型或额度配置时显示。 |
| `troubleshooting` | 故障排查 | 认证、连接、格式兼容与可诊断故障。 | 当 P1 提示失败或提供排查说明时显示。 |

主题入口和卡片链接必须保留现有经验详情路由，不能因为重排把现有经验变为不可达。P1 仅携带主题、来源页面和可选的非敏感场景标识；不得把服务密钥（API Key）、服务地址、账号、订阅信息或弹窗正文拼进统一资源定位符（URL）。详情页若收到来源上下文，提供返回 P1 的明确命令；无上下文时返回当前主题或经验中心。

### 卡片与版式

经验中心使用连续的页面区域，不把整个页面再套进漂浮大卡。桌面采用至少两列网格：每张卡有稳定最小宽度、相同的内容骨架和明确焦点状态。卡片从上到下呈现主题标签、标题、摘要、适用对象和“查看经验”行动；更新时间只作辅助信息，不能与标题争夺阅读顺序。筛选控制是可多行排列的按钮组，选中态用文字、边界和色彩共同表达。

移动宽度为 390px 时，网格降为一列，筛选可换行，卡片的最长标题和行动文字完整可见。卡片圆角不超过 8px，页面不出现卡片嵌套卡片、装饰性光球或由内容长度改变布局的控件。首页精选经验复用相同的层级和视觉令牌（token），但可保留比列表更少的项目数。

### 统一视觉与深色主题

首页 P3 是参考风格，不是要复制一个独立主题。实现应提取到公共页面和经验组件可共同消费的表面、边界、正文、次级文字、焦点和状态视觉令牌（token）。浅色主题维持干净的中性底色与有限的青绿强调；深色主题使用深色底层、略浅的导航或卡片表面、可见边界及足够亮的文字，令这四层在视觉上可区分。

公共导航应在容器内两端对齐，并根据可用宽度采用可预测的收纳方式。经验中心可以使用比一般文章页更宽的内容轨道，但应有最大宽度和内边距，不能无限铺满。P1 顶部标签在桌面和移动端都不能只挤在左侧留下割裂底色；当项目数超过可用空间时，采用可操作的水平滚动或显式收纳，并保持当前标签、焦点和切换结果可见。

### 文案与本地化

首页中文定位由“多模型 API 公益体验与开发接入支持”改为经验分享与开发接入导向，推荐文案为“AI 使用经验分享与开发接入支持”。首页短句仍可保留“官方 API 兼容接入 · 多模型直连 · 即刻体验”，但不得再把公益体验作为首页的主定位。托管网关（Managed Gateway）在中文页面改为“本站托管接入”；对应说明中的“服务密钥”“统一接口”“模型切换”“失败回退”“用量额度”均使用中文表达。

英文语言资源（locale）保持完整英文文案，不能通过删除英文键或把中文直接放入英文资源来满足中文页面要求。新加或重命名的本地化键需同时在中文和英文资源中定义。继续保留既定品牌句“歇一会儿，让 AI 接着干。”和品牌口号（rest 是你的，build 交给 AI。），以及对 Codex 工具（Codex）和代码工具（Claude Code）等模型接入服务的准确表述；不增加未经证实的官方关系或服务承诺。

## 需要拍板的问题

当前没有阻塞实现的人类决定。用户已经指定卡片式经验中心、P3 作为参考、经验分享文案、去除中文页孤立英文、以及深色导航需要全宽和对比层级。主题名称、布局的精确列数和收纳控件由实现者在上述不变量内决定。若后续需要改变公开信息架构、引入新的敏感上下文参数或发布到生产，必须新建决定记录，不能把本地热更新预览（HMR）约束解释为发布授权。

## 实施顺序与门禁

1. N1 先统一内容主题和 P1 上下文合同，保证链接与回退路径存在后再移动卡片布局。
2. N2 完成经验网格和首页精选经验的共同信息层级，先以语义测试固定主题、筛选、键盘和链接行为。
3. N3 完成本地化键与首页定位，检查中文页不再出现托管网关（Managed Gateway）、自带密钥（BYOK）等孤立标题。
4. N4 修改公共页容器、导航和 P1 标签，先固定深浅主题状态与移动收纳行为，禁止凭层叠样式表（CSS）截断掩盖溢出。
5. N5 只在上述源码变更完成后扩展回归，并通过本地热更新预览（HMR）记录桌面和移动的深浅主题观察。

本地热更新预览（HMR）命令固定为：

```bash
VITE_DEV_PROXY_TARGET=https://ai.rest2build.lol \
VITE_DEV_PORT=4174 \
pnpm --dir frontend dev --host 127.0.0.1
```

验收访问范围是经验中心地址（`http://127.0.0.1:4174/experiences`）与首页地址（`http://127.0.0.1:4174/home`）；P1 仅在已有授权的本地浏览器会话中查看，不提交、创建、删除或修改远端业务数据。自动验证至少运行前端测试框架（Vitest）关联文件和类型检查。生产构建、嵌入构建、后端、容器构建（Docker）、部署及远端写操作均不在本候选范围内。
