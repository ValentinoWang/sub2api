# Codex 切换本站接入（Sub2API）后的本地对话接续工具：开发 SSOT

## 业务结论与范围

用户换了模型接入方式后，旧任务可能仍引用已经删除的供应商名称，出现供应商缺失报错（`Model provider ... not found`），或因本地索引关联不一致而无法继续。交付一个本地运行、可诊断、可备份、可迁移、可恢复的小工具，并在本站（rest2build）经验分享中提供下载和独立 Codex 处理指令，与用户截图 P1 的 Codex 接入配置形成双向入口。

本轮是文档交付。所有工具、测试、页面和发布步骤均为待实施设计；不把既往人工修复当成这个通用工具已经存在。用户确认的是文档主题和范围，见范围记录（`scope-decision.md`）。机器记录中的 D1 仅表达这一范围确认，F 仅表达现状来源已绑定；二者均不表示产品已验收。

采用 L2：六个开发单元、两个可独立交付的发布、十个总节点、四个阅读视图。当前由一名实现负责人推进，不启动独立执行进程，不引入额外治理平台。产品负责人负责后续独立验收，不能用生成的合同代替批准记录。

### 保护对象与适用边界

| 对象 | 本工具的责任 |
| --- | --- |
| 本地任务记录与索引 | 修复已支持格式中、被用户选中的供应商关联；保留任务身份、消息、附件和归档状态。 |
| 本地 Codex memories | 保留并核对存在性；不迁移、不重写、不上传，不依赖供应商名称。 |
| 配置、profile、项目授权和认证 | 只读识别，不覆盖用户级配置，不修改功能、记忆设置、供应商定义或认证文件。 |
| ChatGPT 网页历史与云端记忆 | 不属于本机任务迁移，不能承诺转入 Codex 或跨账号同步。 |
| 正在进行的请求、WebSocket 和工具调用 | 必须先结束再切换；不保证跨供应商续接正在执行的调用。 |
| Sub2API Redis | 服务端连接粘性，不是 Codex 持久记忆；不清理、不迁移。 |

“适配其他接入方式”表示不写死旧供应商名称，不表示能修复任意客户端版本、删除的历史或任何报错。认证失败、模型不可用、上下文超限和真正丢失的文件必须分类提示，不能靠改供应商关联掩盖。

## 需要拍板的问题

当前没有需要新增人类决策的问题，因此不创建待决问题文档（`openproblem.md`）。操作系统设备、客户端版本、生产下载与签字尚无证据，属于后续验收缺口，分别由 N3、N6 和发布门处理。发现格式未知时停止该对象的迁移，不把猜测转成批准。

## 用户流程与行为约定

1. 用户从 P1 的“切换接入后继续旧对话”入口或经验列表进入同一详情，选择系统，下载完整工具包，或复制独立处理指令。
2. 工具默认诊断，显示实际数据目录、客户端版本、配置来源、可用目标和受影响任务数量。未明确目标时不生成可执行修改。
3. 用户审阅计划中的任务范围和目标。默认“最近 7 天有可验证活动的受影响任务”；提供明确时间范围或指定任务编号。全量历史必须显式选择。无法可靠判断活动时间的任务单列，不自动排除后宣称已全修复。
4. 等待流式响应与工具调用结束，关闭使用同一数据目录的 Codex 桌面端和命令行客户端，再从外部终端执行应用计划。工具不能杀进程或让承载它的当前任务继续执行客户端退出后的写入。
5. 先完成所有对象备份、读回验证和恢复日志，再执行迁移。完成后输出已处理、无需处理、未支持、冲突和待恢复数量，并给出本地备份与报告位置。
6. 重新打开 Codex，打开原任务并继续一轮。文件修复成功与真实接续验证分别记录；失败时根据原始备份和日志恢复。

### 目标解析与错误分类

数据目录解析顺序：显式参数、实际启动环境中的数据根变量（`CODEX_HOME`）、当前用户默认目录；对符号链接解析后的真实路径进行授权范围检查。发现多个可能入口、配置档或启动覆盖时要求明确选择，不能只读默认文件便认定当前进程使用它。

目标解析以所选数据目录及实际启动参数、配置档的有效配置为依据。显式目标参数（`--target-provider`）仅用于选择，必须能在该有效配置中解析；站点场景仅提供候选信息，不能覆盖本地有效配置。用户取消选择时退出且零修改。

内置供应商（`openai`）不要求用户另写定义；自定义名称按大小写精确匹配。大写自定义名称（`OpenAI`）不等同于内置供应商。请求地址决定流量去向，API 密钥或登录凭据参与身份认证，供应商编号是客户端路由关联，三者不能互相替代。

| 检查结果 | 允许动作 |
| --- | --- |
| 原 provider 缺失，目标定义完整且用户已选定 | 生成仅针对所选任务的迁移计划。 |
| 原 provider 仍存在，用户明确要求切换所选旧任务 | 展示源和目标映射，允许计划；不能只因旧 provider 可用而漏掉迁移需求。 |
| 仅换账号、密钥或订阅，任务关联与目标已一致 | 无需迁移，返回成功的无修改结果。 |
| 配置有重复表、TOML 解析失败、目标缺失或多来源冲突 | 只诊断，先修复接入配置后重新规划；不补写伪造定义。 |
| 历史缺失、JSONL 损坏、索引冲突、版本未知 | 列出受影响对象并阻塞该批；允许用户重新选择已支持的子集。 |
| 401、模型不可用、上下文超限或连接中断 | 提示对应故障类别；不自动切模型、换账号或重写消息。 |

### 本地核心及命令

使用 Python 3.11 及以上版本的标准库核心，利用 TOML、JSON、SQLite 和摘要 API；macOS/Linux shell 与 Windows PowerShell 仅作为同一核心的启动封装。首版不自动安装运行时、不请求管理员权限、不放宽 PowerShell 系统策略。无依赖环境时明确提示要求。

| 命令 | 输入与效果 |
| --- | --- |
| `inspect` | 只读识别配置、任务和索引；默认动作。 |
| `plan` | 明确数据根、目标、范围，输出本地计划；不写任何 Codex 原始数据。 |
| `apply` | 消费指定计划并显式确认其摘要；验证停写、备份和输入未漂移后应用。 |
| `verify` | 比较任务身份、允许字段、内容守恒和索引一致性；不冒充客户端接续证明。 |
| `recover` | 检查持久日志与当前状态，仅完成可判定的未完成步骤；发生漂移则停止。 |
| `rollback` | 消费指定备份与运行 ID，逐对象验证迁移后状态后恢复；不自动整库替换。 |

退出码固定为：0 成功或无需修改，2 参数错误，3 不支持或前置条件阻塞，4 输入漂移/并发冲突，5 备份失败，6 写入中断待恢复，7 验证失败。报告另含状态和原因，调用方不得仅凭进程退出就推断历史接续成功。

计划至少包含 `schema_version`、工具版本、随机运行 ID、生成时间、客户端版本、适配器版本、规范化数据根、有效配置摘要、源与目标映射、筛选条件、准确任务 ID、所有相关文件/索引行的前态指纹、允许字段变更及阻塞项。不得包含 API Key、认证文件内容、私人消息或附件正文。含路径和任务 ID 的计划仍属本地私人文件。

报告至少包含阶段、成功/无修改/未支持/冲突计数、结构验证结果、客户端验证状态、备份路径和恢复指令。默认终端输出脱敏，完整计划仅落本地。安装与运行均不发送遥测，不上传任务、记忆或备份。

### 格式适配及只读检查

N1 建立明确的客户端版本、JSONL 记录结构和 SQLite schema 支持矩阵。识别 `sessions`、`archived_sessions` 及实际索引文件，不假定永远存在 `state_5.sqlite`；多个数据库不凭最新修改时间选一个。没有数据库但客户端确实支持纯文件历史的情况走已验证的独立适配器。

首版允许字段是已识别的 `session_meta.payload.model_provider` 及已确认承载同一关联的索引字段。每个任务可能有多个片段；按任务 ID 聚合全部关联，保留父子关系、归档状态、标题和活动时间。发现另有必需 provider 字段则先更新适配器及受保护测试，不能现场扩大搜索替换范围。

使用结构化解析确定语义，再在已知记录边界做最小替换；未涉及记录、消息和附件引用必须逐字节保持。重复键、异常编码、未知必需记录或元数据与索引矛盾均阻塞。不得把任意文本中的供应商名称替换掉。

诊断不得导致原 SQLite 文件、日志或共享内存被创建、修改或检查点整理。采用经测试的只读快照策略；原目录不可写或存在活跃日志而无法一致读取时返回阻塞，不用忽略日志的读取方式报告成功。检查前后指纹必须证明只读承诺。

### 备份、并发与恢复

`apply` 在外部终端运行，先确认同一数据目录无活跃客户端、获取工具互斥锁并重读计划指纹；无法可靠建立停写条件时拒绝写入。该锁不代表 Codex 遵守它，仍须检查目标文件与数据库状态，并在每个提交边界再次验证预期值。

所有备份完成前禁止修改任何原始对象。JSONL 保留原始字节、元数据和摘要；SQLite 使用一致性备份接口并验证完整性，正确包含日志中的已提交状态，不能只复制主数据库。备份清单同时保存所选行前态以支持精准回滚。Unix 使用仅当前用户可读写权限，Windows 验证等价 ACL；失败阻塞。

恢复日志先创建并持久化，备份逐文件读回核对摘要；验证备份可解析且足够恢复所有拟改对象后，才进入写入。磁盘不足、拒绝访问、备份缺项或摘要不符均返回备份失败，原始数据零修改。禁止事后拼接副本再称为迁移前备份。

跨 JSONL 和 SQLite 没有整体原子事务。状态机为 `PLANNED → BACKUP_VERIFIED → STAGED → FILES_APPLIED → INDEX_COMMITTED → VERIFIED`；任何首次写入后的中断进入 `RECOVERY_REQUIRED`，不可声称全量成功。最终回滚状态为 `ROLLED_BACK`，发现未知变化为 `CONFLICT`。

临时文件放在原文件同一文件系统，写完刷新后原子替换；持久日志记录每次操作前后摘要和完成位置。每个数据库内部使用事务与前态条件更新，核对影响行数；多个数据库/文件之间靠日志恢复，不作跨文件原子性承诺。Windows 文件占用、替换语义和断电持久性要有独立测试。

恢复只处理能够由日志、前态和后态判断的步骤。回滚只恢复选中记录和已修改字段；如果原任务已有新消息或相关索引行变化，拒绝覆盖并输出冲突报告。其他任务新产生的数据不得被整库备份覆盖。备份长期保留，由用户另行清理，工具不自动删除。

同一计划重复执行：后态完整匹配则无需修改，前态匹配则允许首次执行，中间态转恢复，任何未知变化均阻塞。应用完成后单独验证所有任务对应关系、允许字段、未改字节及无关数据库行；失败不能输出“已恢复记忆”。

| 人类验收 | 三个系统分别记录用户实际操作和可见结果；验收人及复核人签字后才能宣称人类验收通过。 |

真实接续夹具覆盖官方登录、自定义远端和本地转发作为来源，目标从有效本站配置识别；不能硬编码 `remote_sub2api → sub2api`。同名 provider 仅更换认证属于无修改对照。桌面端未在某平台可用时使用该平台实际支持的 CLI，并在矩阵中明确产品边界，不能制造不存在的桌面端测试。

结构验证与真实推理分开：本地文件校验不调用模型；真实接续只使用受控测试事实和经授权的测试凭据。无模型服务、设备或客户端证据时相应单元保持待验收；不能用另一系统或新建任务成功替代。

人类验收清单未来只创建于 `docs/human-acceptance/CODEX_SESSION_MIGRATION.md`，同步唯一索引。清单只描述用户操作、可见结果、判定和签字；命令、版本、构建、发布、数据库、日志及内部证明归入技术发布文档，公开材料不包含敏感数据。

发布预览先使用项目规定的 Vite 代理和只读公开页面；验收嵌入边界时才构建前端与 Go 产物。生产发布遵守现有维护和回滚流程，对精确候选进行正文、下载字节及摘要回读；Vite 成功不代表线上已经发布。本轮不执行发布。
