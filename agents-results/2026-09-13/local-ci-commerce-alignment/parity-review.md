# Commerce environment parity gate review

Implemented `tools/quality/check_commerce_environment_parity.py` and `tools/quality/tests/test_commerce_environment_parity.py`.

The offline CLI accepts `--dev DEV.json --prod PROD.json --stage artifact|sales --output RESULT.json`. The default stage is `artifact`. The JSON result contains `passed`, `stage`, bounded `blockers`, and `snapshot_sha256.dev/prod` hashes of the exact input bytes. Gate failures and malformed inputs return exit code 1; an unwritable result returns exit code 2. Diagnostics never include supplied field values or unknown field names.

- Artifact parity requires matching version, source commit, image, schema hash, nonempty migration version/checksum sets, and business rules, plus distinct nonempty database identities. Sales-only fields may be absent; supplied fields must follow the sanitized contract.
- Sales parity additionally requires configured merchant/code-secret flags, distinct nonempty code-secret digests, matching logical products and restock policies, disjoint positive goods IDs, unique mapping keys/IDs, positive exact Decimal amounts at CNY/USD 1:1, a CNY 5 / USD 5 product, initial stock and restock count from 1 through 10, a nonnegative threshold at or below target stock, cleared reconciliation, and all seven acceptance booleans true in both snapshots. The seventh required acceptance field is `inventory_reconciled`.
- Product order and migration order are irrelevant. Decimal spellings such as `1`, `1.00`, and `1e0` are numerically equivalent. Purchase/restock enablement may differ between environments; product enablement must agree. Matched disabled products are permitted so the gate can run before enabling sales.
- Unknown fields, missing required fields, incorrect types (including booleans used as integers), NaN/infinity, duplicate JSON keys, oversized snapshots, and malformed JSON block the gate. Domain/URL/plaintext credential fields are outside this sanitized contract and should be omitted by the exporter.

Validation: `python3 -m unittest discover -s tools/quality/tests -p test_commerce_environment_parity.py -v` passed all 35 tests. Tests include actual mismatch and isolation failures, every false/missing acceptance flag, exact high-precision drift, restock-policy drift, invalid restock bounds, empty migration histories, permitted differences/reordering, and CLI exit/hash behavior. Scoped `git diff --check` passed.

This review does not claim local full-CI completion, live environment parity, actual business acceptance, human PASS, or production readiness. The caller must export authoritative sanitized snapshots and enforce a successful sales gate before enabling purchases. Acceptance flags must derive from actual recorded checks; the release documentation must reference those records. This offline checker validates the supplied assertions and does not execute or authenticate human acceptance. No database, network, Git state, or service runtime was changed by this implementation.
