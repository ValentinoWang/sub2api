# 联动小铺 HTTP 脚本本机验证

日期：2026-09-15（Asia/Shanghai）。结果：**只读链路实测通过，自动补货尚未实现或开启。**

用户在本机临时登录页完成商户登录后，脚本保存 Merchant Token 和 Cookie。两个独立命令进程均成功读取商户目录及本地测试商品库存，其中第二次执行前已关闭登录页服务。读取请求由 Python 标准库直接发出，没有使用 Chrome 扩展或浏览器自动化。这证明已保存的登录态可以用于独立 HTTP 脚本，具备继续开发常驻补货服务的基础。

## 本次修复与实现

商户 `/merchantApi/Goods/list` 需要显式传入 `goods_type=card`、`is_proxy=0`、`status=999` 才能读取完整卡密商品目录。首次缺少过滤参数时，接口成功返回空目录。保留[首次回执](acceptance/probe-20260915T215042-9cad15fb.json)及[首次命令回执](acceptance/probe-20260915T215111-2998cae3.json)，不将空结果解释为库存丢失。增加回归测试后补齐过滤参数，后续两次真实运行均读到 10 个商品。

新增 [Python 工具](../../../tools/commerce/ldxp_http_probe.py)、[本机登录表单](../../../tools/commerce/ldxp_http_probe.html)和[针对性测试](../../../tools/quality/tests/test_ldxp_http_probe.py)，用法见[工具说明](../../../tools/commerce/README.md)。凭据留在仓库外的受限文件中，不保存账号密码。输出仅记录商品 ID、配置金额、库存数量和核对状态，不输出 Token、Cookie 或兑换码。

针对性测试覆盖会话复用、文件访问权限、禁止上传路由、拒绝重定向、错误脱敏、登录安全验证分支、分页变化、库存重复与两次扫描不一致、本地表单 Host/Origin/nonce 校验，以及目录过滤和部分成功分类。此工具进入现有 `tools/quality/tests` 发现范围。本次没有运行完整本地 CI，没有修改运行中的应用容器或发布生产。

## 尚待验证的补货链路

- 首次自动配对多个额度与站点；本次只读取已有本地映射。
- 商户未售卡密与本站批次逐码核对；本次只比较商户端两次读取是否一致。
- 少量生成码、上传、读回确认及失败后重试不重复发码。
- 购买发货、兑换、重复兑换及相应库存变化。
- 定时维持每种额度 999 张库存、进程常驻、断网恢复和登录失效通知。
- 生产机执行与长期登录有效期。

后续应复用本站现有批次与补货规则，先在独立测试商品验证“核对 → 缺多少补多少 → 上传后读回 → 重复运行不再补”，再接常驻调度。本报告是本次技术验证记录，不代表人类验收通过或生产补货已开放。
