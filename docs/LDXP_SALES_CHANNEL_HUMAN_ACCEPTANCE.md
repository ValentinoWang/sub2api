# 链动小铺销售渠道：人工验收清单

这份清单给非技术人员使用。人工只判断用户能看到、能操作和能得到的结果；接口、数据库、兑换码生成算法、签名校验和日志由自动化测试及技术人员负责。

## 当前能验收什么

首期只验收这条实际流程：

```text
链动小铺商品付款 → 收到兑换码 → 在 Sub2API 兑换 → 余额到账
```

这不是支付宝或微信支付接入。验收通过后，只能说“链动小铺卡密销售渠道可用”。

## 验收前由技术人员准备

验收人员不需要查代码、运行命令或填写密钥。技术人员只需提前准备好：

- 一个已经配置好的链动小铺商品；
- 一个可用于测试的小批量库存；
- 一个 Sub2API 测试账号；
- 一个可以联系到的技术人员，以便在出现异常时查看后台记录。

技术人员确认准备完成后，验收人员只使用链动小铺页面和 Sub2API 页面完成下面的步骤。

## 首期卡密渠道验收步骤

### 1. 看商品

- [ ] 链动小铺商品名称、售价和商品说明与约定一致。
- [ ] 商品说明明确告诉用户：购买后会得到 Sub2API 兑换码，以及兑换入口在哪里。
- [ ] 商品没有展示错误的套餐、金额或有效期。

### 2. 买一次

- [ ] 使用测试账号完成一次真实或沙箱购买。
- [ ] 链动小铺显示付款成功。
- [ ] 链动小铺发出一个兑换码，订单页面可以再次找到这次订单和发码结果。
- [ ] 兑换码没有被截断、缺字或混入其他文字。

### 3. 兑一次

- [ ] 打开 Sub2API 的兑换页面，输入刚收到的兑换码。
- [ ] 页面提示兑换成功。
- [ ] 账户余额增加的数值与商品说明一致。
- [ ] 退出后重新登录，余额仍然正确。

### 4. 再兑一次

- [ ] 再次输入同一个兑换码。
- [ ] 页面明确提示该码已经使用或不能重复使用。
- [ ] 账户余额没有再次增加。

### 5. 看库存

- [ ] 购买前后，链动小铺的可售数量变化符合这次购买。
- [ ] 技术人员提供的补货数量与链动小铺实际增加的数量一致。
- [ ] 如果数量不一致，必须在验收记录中写明原因和处理人，不能直接判通过。

### 6. 做一次异常体验

- [ ] 在网络中断、页面刷新或重复点击的情况下，用户不会得到两次余额。
- [ ] 如果兑换页面提示失败，恢复网络后可以再次尝试；成功后仍只到账一次。
- [ ] 用户能看懂失败提示，并知道应该联系谁处理。

## 人工通过标准

下面每一项都满足，人工验收才算通过：

- [ ] 商品信息和实际购买结果一致。
- [ ] 付款成功后确实收到兑换码。
- [ ] 兑换码能在 Sub2API 使用，余额到账数值正确。
- [ ] 同一个兑换码第二次使用不会再次增加余额。
- [ ] 购买前后库存变化合理，差异有明确解释。
- [ ] 普通用户不会看到管理功能或商户密钥。
- [ ] 页面没有把链动小铺说成支付宝、微信或 Sub2API 原生支付。

## LDXP 原生支付目前不验收

目前没有经过确认的 LDXP 服务端支付协议，因此本次人工验收不测试“Sub2API 页面直接使用 LDXP 收款”。技术人员也不得用浏览器现象或一张支付结果页证明原生支付已经接入。

只有在 LDXP 提供正式的服务端收款、回调、查单、退款和对账材料，并完成独立技术测试后，才另开一份原生支付验收，不与本清单混用。
