部署后要打开的开关

新功能一律默认关闭，部署本身不会改变站点行为。以下四项在后台「系统设置」里配置， 配置前它们不产生任何效果。

public_status_page_enabled 默认关 开启后 /status 与 /api/v1/public/status 免登录展示渠道监控的聚合状态。 关闭时接口返回 enabled: false，页面显示「尚未开放」。
lifecycle_emails_enabled 默认关 欢迎信、7 天未调用提醒、30 天流失召回。需先配好 SMTP，否则任务空转。 每位用户每种邮件只发一次，可退订。
first_topup_bonus_tiers 默认空 JSON 阶梯，例如 [{"min_amount":10,"bonus_amount":2}]。留空即关闭。 填写后充值页会展示阶梯并高亮当前金额命中的那一档。
xianyu_store_name 默认空 唯一闲鱼店铺名，显示在 /verify/xianyu 与首页页脚。 留空回退到内置默认名「Rest2Build AI 接入实验室」。

审计发现

功能上线后做了一轮四路并行审计。八项发现全部已修并推送，按严重度排列。

严重

保存设置会清空店铺名与首充阶梯

设置页的提交内容是手写对象，漏了这两个键；后端字段是非指针字符串，缺键即绑定为空串并无条件写库。 后果是店铺名永远存不进去，且管理员改任何无关设置都会顺手抹掉已配置的值。 两端都修了：补齐提交内容，后端改为指针语义——缺键保留原值，显式传空串仍可清空。

严重

首充赠送可能重复发钱

原本靠订单审计日志做幂等，但那个唯一键是 (order_id, action)： 同一用户两笔订单并发履约时挡不住，订单退款后下一笔又会被当成「首充」， 而且先加余额后写日志，中间崩溃会让重试再发一次。 改成按用户唯一的领取表，加钱前原子占位；加钱失败释放占位，崩溃则宁可漏发也不重发。

高

公开状态接口从未注册路由

处理器写好了也接进了依赖注入，所以编译毫无问题，但没有任何路由指向它， /api/v1/public/status 实际返回 404。已注册，并加了覆盖测试： 只要处理器集合里有字段没被任何路由引用就失败——这类断裂编译器抓不到。

高

预渲染页标题被品牌注入覆盖

后端的品牌注入会把整个 <title> 换成「站点名 - AI API Gateway」。 预渲染页也走这条路径，只要后台配了站点名，10 个页面的标题就全变成同一个， 每页独立元数据的意义荡然无存。现在预渲染页不再走整体标题品牌化。

中

验证页店铺名写死在构建期

管理员改了店铺名后，不执行 JavaScript 的抓取器仍会看到默认值—— 而这个页面的全部意义就是证明哪家店是真的。改为构建期输出占位符、服务端替换成实际配置值并做转义。

中

生命周期邮件在后台模板列表不可见

三个事件没进事件顺序表，而那个表才是后台模板编辑器的数据源。 发信正常，但管理员无法预览或修改文案。

低

活跃度统计含已删除的密钥

一把很久前删掉的密钥能让沉默用户一直显示为活跃，从而收不到流失召回。已在查询里排除软删除。

低

带扩展名的 URL 绕过设置注入

/codex-cli/index.html 会被原样返回，同一页面产生两份不同的可抓取文档。 现在两种 URL 形态走同一条注入路径。

还需要你拍板

「永不跑路」印章与不承诺永久稳定的原则冲突

首页主视觉右下角那枚红色印章是你明确要的，我保留了。 但你给的运营方案里写明「不承诺永久稳定、绝不封号」。 要对齐方案的话，改一行即可换成「状态公开 · 可随时撤销」——同样是承诺，但可验证。

robots.txt 默认拒绝 GPTBot

搜索爬虫 OAI-SearchBot 与 Googlebot 已放行， 训练爬虫 GPTBot 按方案示例默认拒绝，等于放弃被训练数据收录。 要放开同样改一行。

域名规划尚未定案

方案里是 rest2build.lol 主站加 api / docs / status / subscription 子域， 而当前全站以 ai.rest2build.lol 为准——canonical、站点地图、接入地址都指向它。 定下来之后我把常量与站点地图一并改掉。

上线步骤

  1. 部署最新 main（e1616903）。迁移 233 与 234 会在启动时自动执行。

  2. 确认 schema_migrations 里出现这两条记录，表 user_lifecycle_emails 与 user_first_topup_bonus 已建。

  3. 后台打开 public_status_page_enabled，访问 /status 确认有数据。

  4. 填 xianyu_store_name，保存后访问 /verify/xianyu 确认显示的是你填的名字。

  5. 需要首充活动就填 first_topup_bonus_tiers，到充值页确认阶梯展示正确。

  6. 配好 SMTP 后再打开 lifecycle_emails_enabled。任务启动 2 分钟后首次运行，之后每 30 分钟一轮。

  7. 抽查 /codex-cli 的页面标题是否是它自己的而非站点名——这条能一次性验证预渲染与品牌注入都正常。
