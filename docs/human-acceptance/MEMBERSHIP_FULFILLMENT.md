# 会员充值履约：人类验收清单

这份清单用于验收负责人确认 Codex/GPT Plus、Codex/GPT Pro20x 的用户体验、运营后台和真实履约结果。只有实际操作、权益核对和签字记录可以写入这份清单。

## 当前验收边界

当前需要分别验收 Codex/GPT Plus 和 Codex/GPT Pro20x。两者的实际套餐、周期和目标账号不同，必须分别完成一次真实权益到账检查；一个商品的通过记录不能用于另一个商品。

Claude Max 不属于本清单的首发验收范围，不能购买。没有验收人和复核人的完整签字记录时，只能标记为“待验收”，不得表述为会员商品已经通过人类验收或已经可以销售。

## 开始人工验收前

验收负责人开始前应拿到一个明确的待测商品、一个专用测试账号、与商品及周期匹配的测试充值凭证，以及可以核对的充值前权益状态。测试负责人还应说明本次资料的用途、可能接收资料的合作方类别、保存期限和风险。

验收期间不得面向普通客户开放待测商品，也不得把测试订单当作真实客户收入。任一准备项缺失时，记录阻塞原因并停止验收。

## 客户页面人工验收

分别使用桌面和手机视口、中文和英文完成本节，并在记录中注明浏览器、系统、语言和时间。

### 1. 商品与品牌边界

- [ ] 打开 `/memberships`，只看到本站定义的商品名、价格、预计时效、库存/停售状态和服务说明。
- [ ] Codex 与 GPT 被说明为同一权益的使用场景和展示名称，不出现可对同一账号重复购买两份权益的误导。
- [ ] Plus 与 Pro20x 的套餐、周期、凭证类型和预计时效清楚分开。
- [ ] Claude Max 显示为待供应商验证或不可购买，不能进入付款流程。
- [ ] 页面没有声称本站是 OpenAI、Anthropic 或其他模型厂商的官方服务、授权代表或自主完成全部底层充值。
- [ ] 条款清楚说明服务可能由授权合作方履约；需要向合作方发送 Session、Token 或账号数据时要求单独明确同意。

### 2. 资料、同意与状态

- [ ] Account ID/User ID 模式优先；只有当前商品确实需要时才显示 Session 输入。
- [ ] 提交前可以阅读数据用途、接收方类别、保存期限、风险和条款版本。
- [ ] 未勾选明确同意时不能提交资料；切换到同意范围之外的合作方时会重新征求同意。
- [ ] 客户只看到本站订单号、脱敏账号、归一化状态和当前可执行操作。
- [ ] 时间线能清楚区分待付款、待补资料、排队中、充值中、待复核、成功、失败、退款中和已退款。
- [ ] 页面没有显示供应商域名、供应商 CDK、上游任务编号、内部尝试编号、供应商错误码或原始响应。
- [ ] 刷新页面、退出后重新登录或更换设备后，订单状态仍然一致。

### 3. RTT 与分享卡片

- [ ] 进入页面后立即开始测速，并在 5 秒内完成 3 次测量，显示其中最小 RTT。
- [ ] 一轮结束后等待 5 秒自动开始下一轮；响应返回后立即更新，延迟升高和降低都如实显示。
- [ ] 单次请求超过 5 秒或测速失败时清除旧值并显示不可用，之后自动重试。
- [ ] 页面切到后台后停止测速；返回页面或恢复联网时立即重新测速。
- [ ] 分享卡片预览中的 RTT 随最新测量重绘。
- [ ] 下载 PNG 后，图片保留导出时的静态 RTT，不随页面后续测量变化。

### 4. 失败、退款和售后

- [ ] 付款成功只表示已付款，不会立即显示为已充值。
- [ ] 资料失效、账号不符合条件、库存不足、处理中、结果待确认和履约失败使用本站统一提示。
- [ ] 未知提交结果进入待复核，不会自动再次提交、换 CDK 或切换供应商。
- [ ] 重复点击、刷新、重复支付回调或任务重试不会产生第二次充值。
- [ ] 退款申请会冻结后续提交；结果不明时先复核，确认未交付后才原路退款。
- [ ] 客户可以从本站订单页进入售后，不需要访问供应商网站或提供供应商任务号。

## 人工通过标准

只有下面条件全部满足，才能把对应 SKU 标记为“人类验收通过”：

- [ ] 客户页面与后台在桌面、手机、中文和英文环境下全部通过。
- [ ] Plus 与 Pro20x 分别具有一次真实、授权、可核对权益变化的成功记录。
- [ ] 成功、资料失效、库存不足、超时、结果待确认和人工复核的用户体验均已检查。
- [ ] 页面刷新、重复点击和人工重试均未造成重复充值。
- [ ] 客户页面、通知和下载内容中没有供应商域名、CDK、内部任务编号或原始错误码。
- [ ] 退款、补发、人工接管和对账结果均符合规则。
- [ ] 验收人和复核人均签字，并明确只批准已验证的 SKU、通道、凭证模式和周期。

即使本清单通过，启用支付和开售仍是单独的发布动作。开售前必须重新检查实时库存、通道可用性、商品验证时间、支付配置和停售开关。
