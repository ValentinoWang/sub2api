# 上游整合后的人类验收清单

这份清单用于验收负责人实际查看和操作本次上游整合后的用户页面、登录、通道状态、支付说明和代理管理。所有项目默认保持“待验收”；只有实际操作、观察结果和双人签字可以改变结论。

## 开始前

- [ ] 准备一个普通用户账号和一个管理员账号。
- [ ] 确认测试期间允许查看公开页面、登录页面、用户通道状态和管理员代理页面。
- [ ] 涉及付款、真实充值、兑换或账号权益变化时，先取得对应业务的单独授权；没有授权时只检查页面展示，不提交真实交易。
- [ ] 分别准备桌面和手机浏览器，并能够切换浅色、深色主题。

任一账号、权限或测试资料缺失时，在验收记录中标为“阻塞”，不要用其他页面的结果代替。

## 公开页面与主题

- [ ] 打开首页，页面顶部、主体和底部只有一套一致的视觉主题，没有重复底部状态或两套互相冲突的页脚。
- [ ] 首页底部显示 `rest2build`、`歇一会儿，让 AI 接着干。`、`rest 是你的，build 交给 AI。`，以及包含“AI 模型接入服务、账号充值、公益 Skills、AI 使用经验分享与 Harness 工程”的完整介绍。
- [ ] 打开经验分享页，经验以清晰的卡片展示；Codex CLI、Claude Code 和 OpenAI 兼容接口内容作为经验主题进入，不再表现为彼此割裂的独立栏目。
- [ ] 从经验卡片进入详情，再返回经验列表，入口、标题和返回路径都正确。
- [ ] 打开公开公益、性能对比、企业发票等页面，页脚宽度、品牌信息、颜色和首页、经验分享页一致。
- [ ] 浅色主题下，状态色、提示色和背景有足够区分；深色主题下，底层背景和内容区域具有清楚对比。
- [ ] 桌面宽屏下主要内容合理占满可用宽度；手机下没有横向滚动、文字遮挡或按钮溢出。

## 登录与注册入口

- [ ] 当允许注册时，登录页显示清楚的注册入口，点击后进入可用的注册流程。
- [ ] 当停止注册时，登录页不显示可操作的注册入口，也不会通过空白区域或错误链接进入注册页。
- [ ] 登录表单和底部品牌区宽度协调，在桌面和手机上都不会异常变窄或溢出。
- [ ] 使用正确账号可以登录，错误账号信息得到可理解的错误提示，不暴露内部错误内容。

## 通道状态

- [ ] 当通道状态功能关闭时，普通用户看到明确的不可用状态，页面不会持续加载或反复刷新。
- [ ] 网络较慢时显示加载状态；请求失败时显示错误状态并提供可用的重试入口。
- [ ] 没有通道数据时显示空状态，不把空数据误报为健康或故障。
- [ ] 有数据时，模型、通道、延迟、吞吐和额度等允许展示的信息与页面筛选结果一致。
- [ ] 当用户排行可见时可以进入排行视图；当排行被隐藏时，看不到排行入口，已有排行地址也不会留下空白视图。
- [ ] 首字节时间没有样本时显示中性状态，不显示成功、失败或伪造数值。
- [ ] 切换标签、刷新页面和从后台回到页面后，内容不会重叠、重复或停留在过期状态。

## 支付说明与安全展示

- [ ] 打开充值或支付页面，帮助说明中的标题、段落、列表和链接排版正确。
- [ ] 帮助说明里的正常链接可以点击，并在预期位置打开。
- [ ] 使用包含脚本、事件属性或危险链接的测试说明时，危险内容不会执行，也不会形成可点击的危险入口。
- [ ] 当充值换算倍率不为 `1` 时，页面显示的实际到账余额正确，首充赠金高亮档位也按该到账余额选择；低于、等于和高于档位边界时都与最终到账结果一致。
- [ ] 在会员商品中输入前后带空格的优惠券后创建订单，页面按优惠券实际结果显示价格或错误；不输入优惠券时仍可正常创建订单。
- [ ] 进入人工复核状态的会员订单只显示等待处理状态，不显示“继续支付”入口；正常待支付订单仍可继续支付。
- [ ] 自定义内容中的脚本、事件属性、危险地址、相对地址和未经允许的外部嵌入页都不会被加载；允许展示的嵌入页不能弹窗、打开新窗口或获得不必要的页面权限。
- [ ] 页面清楚区分账号充值服务、余额充值、会员履约和链动小铺兑换，不把其中一种说成另一种。
- [ ] 没有真实交易授权时，验收到展示和安全过滤为止，不点击最终付款、兑换或提交按钮。

会员充值实际履约继续按照 [会员充值履约清单](MEMBERSHIP_FULFILLMENT.md) 分别验收每个商品；链动小铺购买、发码与兑换继续按照 [链动小铺销售渠道清单](LDXP_SALES_CHANNEL.md) 验收。

## 代理管理

- [ ] 打开代理管理页，新增和编辑表单能够清楚区分名称、地址、到期时间、备用代理及其他可选项。
- [ ] 只修改一个字段并保存时，其他未修改字段保持原值。
- [ ] 清空一个允许清空的可选字段后保存，该字段确实清空，其他字段保持原值。
- [ ] 分别清空代理用户名和密码后保存，重新打开时旧凭据不再出现；没有编辑这两个字段时，原值保持不变。
- [ ] 输入无效日期、结束时间早于开始时间或格式错误的时间时，页面阻止保存并显示可理解的提示。
- [ ] 选择备用代理后保存并重新打开，关联关系保持正确。
- [ ] 删除正在被其他代理作为备用项引用的代理时，页面明确拒绝删除；批量删除时也不会留下指向不存在对象的备用关系。
- [ ] 修改代理地址、端口或认证信息后，列表不会继续显示修改前的出口地址、地区、延迟或质量结果；重新检查完成后才显示与新代理一致的结果。
- [ ] 同时从两个窗口修改同一代理的不同字段后刷新，两个成功保存的字段都保留，没有后提交的请求恢复另一个字段的旧值。

## 模型与账号探测

- [ ] 管理员对 MiniMax、Grok、Ollama Cloud、Image 2.5 和 Claude 账号分别执行页面提供的检查操作。
- [ ] 成功时显示对应模型或账号的可用结果；失败时显示可理解的失败原因，不展示令牌、Cookie、认证头或供应商原始响应。
- [ ] 取消一个正在进行的检查后，页面及时停止等待，可以继续进行其他操作。
- [ ] 检查完成后刷新页面，账号状态与最后一次明确完成的结果一致，不把已取消的检查记为成功。

## Codex 旧对话接续

Codex 本地旧对话迁移继续按照 [Codex 本地旧对话接续清单](CODEX_SESSION_MIGRATION.md) 验收。本清单的页面通过不能代替旧任务的诊断、迁移、重开和记忆连续性检查。

## 通过、不通过与阻塞

- **通过**：本清单中适用项目全部完成，观察结果符合描述，未发现会阻止用户使用的问题，验收人和复核人均签字。
- **不通过**：任一适用项目出现错误、危险内容被执行、数据被意外改动、页面无法完成预期操作，或桌面/手机任一端存在阻断问题。
- **阻塞**：缺少账号、权限、测试资料、业务授权或可观察数据，导致项目无法实际执行。
