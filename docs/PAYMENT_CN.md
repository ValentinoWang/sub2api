## 支持的支付方式

| 服务商 | 支付方式 | 说明 |
|--------|---------|------|
| **EasyPay（易支付）** | 支付宝、微信支付 | 兼容易支付协议的第三方聚合支付 |
| **支付宝官方** | 桌面二维码扫码、移动端支付宝跳转或当面付唤起 | 直接对接支付宝开放平台；移动端默认 WAP，也可选择当面付二维码唤起支付宝 |
| **微信官方** | Native 扫码、H5、公众号/JSAPI 支付 | 直接对接微信支付 APIv3，按终端环境自动分流 |
| **Stripe** | 银行卡、支付宝、微信支付、Link 等 | 国际支付，支持多币种 |
| **Airwallex（空中云汇）** | 卡、钱包及本地支付方式（按账户开通能力） | 通过 Payment Acceptance API 和 Webhook 对接 |

> 支付宝官方 / 微信官方与易支付可以同时作为后台服务商实例存在，内置支付宝、微信方式对用户统一显示为 `支付宝`、`微信支付`。实际来源取决于启用的实例及已有路由配置，见下方“前台可见支付方式路由”。费用和结算规则以所选机构及商户合同为准。

> **支付 FM**：可通过现有 **EasyPay（易支付）** 服务商配置其兼容模式，具体见[支付 FM 接入](#支付-fm-接入)。下单、通知的协议对应关系已核对；主动查单、自动退款及同步跳转长度仍有接入限制，不能视为完整实单验证通过。

> **易支付服务商推荐**：以下两家均为兼容易支付协议的第三方聚合支付，按资金通道与结算方式选择：
>
> - **国内渠道 / 人民币结算** — [ZPay](https://z-pay.cn/?uid=23808)（`https://z-pay.cn/?uid=23808`）：支付宝 / 微信官方 API 直连，手续费 **1.6%**；资金直达商家账户，**T+1 自动到账**。支持**个人用户**（无营业执照）每日 1 万元以内交易；拥有营业执照则无限额。
> - **国际渠道 / USDT 或美元结算** — [启润支付](https://merchant.kyrenpay.com/?code=SUB2API)（`https://merchant.kyrenpay.com/?code=SUB2API`）：为 AI 项目提供低门槛国际收款通道，支持国际版微信支付与支付宝，本地货币支付、美元结算。微信 2.5%、支付宝 2.5%；多种提现方式，海外公司账户提现手续费 20 美金，USDT 提现手续费 30 美金 + 0.4% 流水，以 **USDT 或美元** 到账。无资质审核、注册即用，使用门槛最低；提现门槛略高，适合**不使用国内支付渠道、无法接受 Stripe 高达 6%+ 手续费、流水较大，且拥有美元或 USDT 渠道可接收提现资金**的用户。启润支付开户费 200 美元，通过本链接注册（含 Sub2Api 作者 [@Wei-Shaw](https://github.com/Wei-Shaw) 邀请码）可**免开户费**，介意可去掉。
>
> 支付渠道的安全性、稳定性及合规性请自行鉴别，本项目不对任何第三方支付服务商做担保或背书。

## 快速开始

1. 进入管理后台 → **设置** → **支付设置** 标签页
2. 开启 **启用支付**
3. 配置基本参数（金额范围、超时时间等）
4. 在 **服务商管理** 中添加至少一个服务商实例
5. 用户即可在前端页面进行充值

## 系统设置

在管理后台 **设置 → 支付设置** 中配置以下参数：

### 基本设置

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| **启用支付** | 启用或禁用支付系统 | 关闭 |
| **商品名前缀** | 支付页面显示的商品名前缀 | - |
| **商品名后缀** | 商品名后缀（如"元"） | - |
| **最低金额** | 单笔最低充值金额 | 1 |
| **最高金额** | 单笔最高充值金额（留空表示不限制） | - |
| **每日限额** | 每用户每日累计充值上限（留空表示不限制） | - |
| **订单超时时间** | 订单超时分钟数，至少 1 分钟 | 30 |
| **最大待支付订单数** | 同一用户最大并行待支付订单数 | 3 |
| **负载均衡策略** | 多服务商实例时的选择策略 | 轮询 |

### 支付宝移动端当面付唤起

`支付宝移动端当面付唤起` 默认关闭，仅对前台路由到 **支付宝官方** 的移动端订单生效。开启后，服务端调用 `alipay.trade.precreate` 获取动态二维码，前端立即使用支付宝 Scheme 尝试唤起 App；页面未进入后台时会自动展示动态二维码备用页，继续轮询订单状态。桌面端使用当面付二维码或电脑网站支付。

- 需要为该支付宝应用开通 **当面付 / 扫码支付**；未开通时保持关闭。
- 管理后台开关保存为 `ALIPAY_MOBILE_PRECREATE_DEEP_LINK`；部署环境变量 `ALIPAY_MOBILE_PRECREATE_DEEP_LINK=true` 可强制开启，未设置时使用后台值。
- 与“支付宝强制二维码支付”同时开启时，当面付唤起优先。关闭本开关即可恢复移动端手机网站支付。

### 前台可见支付方式路由

当前管理页面通过 **服务商管理** 配置实例的启停和支持方式，已不提供独立的“前台可见支付方式”来源选择控件：

- 内置支付宝、微信按钮不以服务商名称区分；易支付实例需勾选实际开通的支付宝或微信方式。
- 同一方式只有一种已启用的服务商类型时，后端可直接确定来源。
- 同一方式同时存在官方和易支付实例时，后端仍会读取已有来源配置；没有有效来源时可能出现方式可见但无法下单。首次接入支付 FM 时，先停用同一支付方式的其他服务商实例，避免测试订单被分配到其他商户。
- 同类型多个实例仍可能按负载均衡策略分配订单。验证支付 FM 时应确认订单实际选中的实例。

### 负载均衡策略

| 策略 | 说明 |
|------|------|
| **轮询（round-robin）** | 按顺序轮流分配到各服务商实例 |
| **最少金额（least-amount）** | 优先分配到当日累计金额最少的实例 |

### 取消频率限制

防止用户频繁创建并取消订单：

| 设置项 | 说明 |
|--------|------|
| **启用限制** | 开关 |
| **窗口模式** | 滚动窗口 / 固定窗口 |
| **时间窗口** | 窗口长度 |
| **窗口单位** | 分钟 / 小时 |
| **最大次数** | 窗口内允许的最大取消次数 |

### 帮助信息

| 设置项 | 说明 |
|--------|------|
| **帮助图片** | 充值页面显示的客服二维码等图片（支持上传） |
| **帮助文本** | 充值页面显示的说明文字 |

## 服务商配置

每种服务商需要不同的凭证和参数。在 **服务商管理 → 添加服务商** 中选择类型后填写。

> **回调地址自动生成**：异步通知和同步跳转的基础地址可分别编辑，留空时使用当前管理页面域名，系统追加固定路径。通过 localhost、内网地址或运维域名访问后台时，必须改为对应的公网地址；前后端分域部署时，异步通知指向后端 API，同步跳转指向前端站点。

### EasyPay（易支付）

实现传统 EasyPay 的 MD5 签名、`submit.php` 跳转支付和 `mapi.php` 表单下单。不同平台的兼容范围可能只覆盖下单及通知，查询和退款需要分别确认；不能仅凭“支持易支付”判断全部功能可用。

| 参数 | 说明 | 必填 |
|------|------|------|
| **商户 ID（PID）** | EasyPay 商户 ID | 是 |
| **商户密钥（PKey）** | EasyPay 商户密钥 | 是 |
| **API 地址** | EasyPay API 基础地址 | 是 |
| **支付宝通道 ID** | 指定支付宝通道（可选） | 否 |
| **微信通道 ID** | 指定微信通道（可选） | 否 |

支付模式为 **二维码**（`qrcode`）时，后端向 `mapi.php` 发起 POST；为 **弹窗**（`popup`）时，生成 `submit.php` 签名链接供浏览器打开。上游只返回支付链接时，并不保证本站能直接展示原生支付二维码。

### 支付宝官方

直接对接支付宝开放平台。移动端默认走支付宝手机网站支付跳转；开启“支付宝移动端当面付唤起”后改为调用当面付，前端尝试打开支付宝 App，失败时显示动态二维码备用页。桌面端优先使用当面付返回扫码串，未开通当面付时使用电脑网站支付，并将收银台链接同时返回给前端用于渲染二维码或直接打开支付页。

| 参数 | 说明 | 必填 |
|------|------|------|
| **AppID** | 支付宝应用 AppID | 是 |
| **应用私钥** | RSA2 应用私钥 | 是 |
| **支付宝公钥** | 支付宝公钥 | 是 |

### 微信官方

直接对接微信支付 APIv3，支持 Native 扫码支付、H5 支付，以及在微信环境内的公众号/JSAPI 支付。

| 参数 | 说明 | 必填 |
|------|------|------|
| **AppID** | 微信支付 AppID | 是 |
| **商户号（MchID）** | 微信支付商户号 | 是 |
| **商户 API 私钥** | 商户 API 私钥（PEM 格式） | 是 |
| **APIv3 密钥** | 32 位 APIv3 密钥 | 是 |
| **微信支付公钥** | 微信支付公钥（PEM 格式） | 是 |
| **微信支付公钥 ID** | 微信支付公钥 ID | 是 |
| **商户证书序列号** | 商户证书序列号 | 是 |

### Stripe

国际支付平台，支持多种支付方式和币种。

| 参数 | 说明 | 必填 |
|------|------|------|
| **Secret Key** | Stripe 密钥（`sk_live_...` 或 `sk_test_...`） | 是 |
| **Publishable Key** | Stripe 可公开密钥（`pk_live_...` 或 `pk_test_...`） | 是 |
| **Webhook Secret** | Stripe Webhook 签名密钥（`whsec_...`） | 是 |

## 支付 FM 接入

### 接入结论与边界

支付 FM 官方提供“易支付系免开发接入”，本项目应选择 **EasyPay（易支付）** 实例，实例名称可填写“支付 FM”。无需新增一个名为 `zhifufm` 的服务商类型，也不应把 FM 的接入密钥填入“支付宝官方”或“微信官方”的凭证字段。

这里使用 FM 的**易支付兼容接口 2.0**，不是对其原生 API 的完整适配，也不代表支持其他平台所称的 RSA 易支付 V2。按 2026-09-07 读取的官方文档与当前源码，能力对应如下：

| 能力 | 官方协议与当前实现 | 接入判断 |
|------|-------------------|----------|
| 跳转下单 | FM 支持 GET/POST 跳转；项目生成 `API 基础地址 + /submit.php` 的 GET 签名链接 | 协议对应，需确认商户提供的实际路径及同步跳转长度 |
| 后端下单 | FM 接受表单 POST，返回 `code=1`、`trade_no`、`payurl`；项目调用 `API 基础地址 + /mapi.php` | 核心字段对应；FM 明确 `qrcode` 不传值，应按支付链接验收 |
| 支付通知 | FM 使用 GET、MD5、`trade_status=TRADE_SUCCESS`，要求返回纯文本 `success` | 项目已有 GET 路由和验签处理；实际回调可达性及到账仍需实单证明 |
| 主动查单 | 项目调用 `/api.php`，发送 `act=order`、`pid`、`key`、`out_trade_no`；FM 公开文档给出原生 `/queryOutOrder`，使用 `merchantNum`、`orderNo` 及另一种签名 | 不是同一协议。未找到官方对上述易支付查单接口的保证，不能承诺漏单自动补偿可用 |
| 自动退款 | 项目调用 `/api.php?act=refund`；已查阅的 FM 兼容文档未说明该退款接口 | 保持实例“允许退款”关闭，取得接口证据并验证前不启用 |
| 同步跳转 | FM 跳转下单文档要求 `return_url` 在 200 字符以内；项目可能追加 `order_id`、`out_trade_no`、`resume_token` 等参数 | 存在超长风险。短的后台基础地址不能保证最终请求合规，必须核对实际请求 |

因此，当前结论是**已有可用于对接的下单和通知实现，尚不能声明支付 FM 完整支付闭环可直接投入生产**。如果商户网关不支持当前查询路径、严格限制跳转长度或使用不同端点，需要补充代码适配；改文档或换一个 API 域名不能解决协议差异。

### 在支付 FM 准备收款能力

1. 登录[支付 FM 商户后台](https://wmp.zhifux.com/)，根据[接入指引](https://docs.zhifux.com/read/zhifufm/step)完成对应收款账号配置。只有 PID 和密钥，还不能收款。
2. 根据自己的资质和使用场景选择[支付产品](https://docs.zhifux.com/read/zhifufm/paytype)。签约类型需开通具体支付产品；免签类型按所选方式配置监测服务，不能认为 Sub2API 会代替收款监测。
3. 在 **用户中心 → API 开发信息** 查看商户号、接入密钥、跳转接口地址和 JSON 方式接口地址。
4. 在 FM 的 **支付方式关联 / v2 关联** 中，把 `alipay`、`wxpay` 关联到已经配置的收款产品。官方说明默认关联收款码方式，签约类型需要调整关联。Sub2API 中仍选择支付宝、微信，无需把 `wxpay` 手动改成 `wechat` 或把产品代码填进通道 ID。

费用、可用产品、额度和结算方式以当前 FM 后台及对应支付机构约定为准；本节不预设费率或到账时间。

### Sub2API 字段填写

进入 `/admin/settings` → **支付设置**，开启“启用支付”，配置充值金额范围并保存；在服务商类型中启用易支付，然后在 **服务商管理 → 添加服务商** 中填写：

| Sub2API 字段 | 支付 FM 对应内容 / 建议值 |
|-------------|-------------------------|
| 服务商类型 | EasyPay（易支付） |
| 服务商名称 | 支付 FM，或能区分测试与正式商户的名称 |
| PID | 用户中心的**商户号**，不是登录用户名；按原字符串完整填写 |
| PKey | 用户中心的**接入密钥**，不是收款账户密码、支付宝私钥或微信 APIv3 密钥 |
| API 基础地址 | 从 FM 提供的**跳转接口地址 / JSON 方式接口地址**提取公共基础路径，保留路径前缀，去掉末尾 `submit.php` / `mapi.php` |
| 支持的支付方式 | 只勾选已在 FM 配置并关联的支付宝、微信 |
| 支付模式 | 首次可选“弹窗”打开 FM 收银台；“二维码”调用 JSON 下单接口，但 FM 主要返回 `payurl`，名称不代表直接返回二维码 |
| 支付宝通道 ID / 微信通道 ID | 默认留空。当前兼容文档未定义本项目发送的 `cid`；FM 的“支付方式关联”不等于该字段 |
| 异步通知地址的基础部分 | Sub2API 公网 API 地址，系统追加 `/api/v1/payment/webhook/easypay` |
| 同步跳转地址的基础部分 | Sub2API 公网前端地址，系统追加 `/payment/result`；最终下单可能使用请求携带的前端地址及恢复参数 |
| 启用 | 在受控测试环境启用；确认同一支付方式没有其他实例干扰 |
| 允许退款 | 关闭，直到 FM 对应接口完成适配及验证 |

**API 基础地址必须来自该商户的兼容接口地址。** `https://docs.zhifux.com` 是文档站，`https://wmp.zhifux.com` 是商户后台，都不能直接当作支付网关。也不要把原生 API 的“接口根地址”未经核对填进来。

例如，若商户后台实际给出 `https://gateway.example/epay/submit.php` 和 `https://gateway.example/epay/mapi.php`，则填写 `https://gateway.example/epay`。这只是格式示例，**不是支付 FM 的真实网关地址**。当前代码也能去除完整地址末尾的已知 PHP 文件名，但会丢弃 query 和 fragment；若官方地址依赖查询参数或其他路径形式，需先适配，不能直接照填。

### 通知、金额与到账

同域部署时，地址形如：

```text
异步通知：https://your-domain.com/api/v1/payment/webhook/easypay
同步跳转：https://your-domain.com/payment/result
```

下单时由 Sub2API 传给 FM，无需自行编写回调脚本。异步通知必须能从公网直接 GET 访问，不能经过登录页、验证码或 301/302 跳转。FM 文档要求默认 3 秒内应答，并会在通知失败后重试；站点代理和后端处理时间需要满足该要求。

签名按参数名 ASCII 升序排列，排除 `sign`、`sign_type` 和空值，以未经 URL 编码的值拼接，再直接追加接入密钥，计算小写 MD5。项目已有实现；不要把拼接后的待签名字符串或密钥记录到普通日志。

支付成功应以**真实 Sub2API 订单进入 `COMPLETED` 且余额或订阅权益实际到账**为准。打开 `/payment/result`、页面显示支付成功或单独访问回调得到 `success`，均不能证明完成收款：项目对部分未知订单也会应答 `success` 以停止无效通知。同步跳转只用于返回页面，不能代替异步通知。

FM 的 `money` 单位为人民币元，最多两位小数，对应 Sub2API 订单的实际支付金额 `pay_amount`。Sub2API 的余额入账额度可能受充值倍率等设置影响，不应把付款人民币金额直接当成入账余额。验证时分别对照订单应付金额、FM 实付记录、Sub2API 预期入账额度及实际余额变化。

### 验证范围与未决项

本次文档更新核对了官方接口说明及本地代码。它不代表已配置用户的商户、不代表已经下单、付款、收到真实通知或退款。静态核对和本地模拟测试也不能替代这些交易证据。

2026-09-07 已在 `backend` 目录运行 `go test ./internal/payment/provider -run 'Test(EasyPay|NormalizeEasyPay|ResolveEasyPay|SummarizeEasyPay)' -count=1` 并通过，覆盖现有签名、地址处理、查询状态解析和退款响应等本地用例；这些测试使用本地输入或模拟服务，不是 FM 商户接口联调结果。

联调应在测试环境先完成以下顺序：

1. 在支付前核对最终端点、`type`、金额及 `return_url` 长度。FM 文档对订单号字符和长度的描述存在歧义，需以商户网关接受的真实订单请求核实，不能照抄示例认定所有本地订单号可用。
2. 使用已开通通道允许的最小测试金额，确认能够打开对应 FM 收银台；分别验证计划使用的桌面和手机场景。不要把“二维码”模式有返回链接当作扫码体验已经通过。
3. 小额付款后，在双方后台按商户订单号对应订单，确认 FM 已支付、Sub2API `COMPLETED`、权益只入账一次。测试记录保留脱敏订单号、金额、状态、时间和实例标识，不保存密钥或完整恢复链接。
4. 在隔离测试中验证重复通知不重复入账、错误签名和错误金额不入账。若要启用漏单补偿或退款，先解决上表协议缺口，再验证通知丢失、订单超时和退款结果；不能用手动修改订单成功状态代替验证。

FM 原生商户订单查询文档目前注明 **VIP 用户且需联系客服申请**。即使已经申请，也只是取得该原生接口的使用资格，本项目不会因此自动切换到 `/queryOutOrder`。需要完整的 FM 支持时，后续开发至少应覆盖：查单协议与状态映射、最终返回地址长度处理、退款能力确认，以及真实通知时延和重复通知验证。

### 常见问题

| 现象 | 定位方向 |
|------|----------|
| 服务商类型无法选择易支付 | 先在支付设置上方启用该服务商类型并保存 |
| 跳到非收银台页面、404 或 JSON 解析失败 | 检查是否误填文档站/后台地址、丢失路径前缀，或商户端点并非 `submit.php` / `mapi.php` |
| 无可用支付方式或下单失败 | 检查实例启用状态、支持方式、金额限额及同一方式的其他服务商来源 |
| FM 提示无收款号或通道不可用 | 检查 FM 收款账号、支付产品开通及 v2 支付方式关联；免签方式还需检查监测状态 |
| 签名错误 | 检查 PID 与接入密钥是否属于同一商户、是否误填其他密钥，以及代理是否改写签名参数 |
| “二维码”模式没有原生二维码 | FM 文档说明 `qrcode` 不传值；检查 `payurl` 能否打开对应收银台 |
| 已付款但未到账 | 对照双方订单和通知记录，检查回调域名、GET 可达性、3 秒应答、验签及金额校验；未确认查单兼容前不能假定后台会自动补单 |
| 付款后未返回站点或提示地址太长 | 检查最终 `return_url` 是否超过 200 字符；部分手机支付方式本身不保证跳回，到账仍以订单和权益为准 |
| 查询或退款接口报错 | 按上表确认协议与商户权限，不要通过更换基础地址影响已可用的下单接口 |

## 服务商实例管理

同一种服务商可以创建**多个实例**，实现负载均衡和风控：

- **多实例负载均衡** — 按轮询或最少金额策略分流订单
- **独立限额** — 每个实例可独立配置单笔最小/最大金额和每日限额
- **独立启停** — 可单独启用/禁用某个实例，不影响其他实例
- **退款控制** — 每个实例可单独开启或关闭退款功能
- **支付方式** — 每个实例可选择支持的支付方式子集
- **排序** — 拖拽调整实例顺序

### 实例限额配置

每个实例支持以下限额：

| 限额项 | 说明 |
|--------|------|
| **单笔最小金额** | 该实例接受的最小订单金额 |
| **单笔最大金额** | 该实例接受的最大订单金额 |
| **每日限额** | 该实例每日累计交易上限 |

> 负载均衡时，系统会自动跳过超出限额的实例。

## Webhook 配置

支付回调是支付系统的核心环节，必须正确配置：

### 回调地址格式

添加服务商时，系统会自动根据站点域名拼接回调地址，格式如下：

| 服务商 | 回调路径 |
|--------|---------|
| **EasyPay** | `https://your-domain.com/api/v1/payment/webhook/easypay` |
| **支付宝官方** | `https://your-domain.com/api/v1/payment/webhook/alipay` |
| **微信官方** | `https://your-domain.com/api/v1/payment/webhook/wxpay` |
| **Stripe** | `https://your-domain.com/api/v1/payment/webhook/stripe` |

> 将 `your-domain.com` 替换为实际可访问后端 API 的公网域名。EasyPay / 支付宝 / 微信在添加服务商时自动追加固定路径；基础域名仍需确认，尤其不要保留 localhost 或仅供运维访问的地址。支付 FM 使用本表中的 EasyPay 地址。

### Stripe Webhook 设置

1. 登录 [Stripe Dashboard](https://dashboard.stripe.com/)
2. 进入 **Developers → Webhooks**
3. 添加端点，填写回调地址
4. 订阅事件：`payment_intent.succeeded`、`payment_intent.payment_failed`
5. 将生成的 Webhook Secret（`whsec_...`）填入服务商配置

### 注意事项

- 回调地址必须是 **HTTPS**（Stripe 强制要求，其他服务商强烈推荐）
- 确保服务器防火墙允许支付平台的回调请求
- 系统会自动进行签名验证，防止伪造回调
- 支付成功后自动完成余额充值，无需人工干预

## 支付流程

```
用户选择充值金额和支付方式
       │
       ▼
  创建订单 (PENDING)
  ├─ 校验金额范围、待支付订单数、每日限额
  ├─ 负载均衡选择服务商实例
  └─ 调用服务商获取支付信息
       │
       ▼
  用户完成支付
  ├─ EasyPay    → 扫码 / H5 跳转
  ├─ 支付宝官方  → 桌面扫码单（当面付或电脑网站支付）/ 移动端 WAP 或当面付唤起 + 动态二维码备用页
  ├─ 微信官方    → 桌面 Native 扫码 / 非微信 H5 / 微信内 JSAPI
  └─ Stripe     → Payment Element（银行卡/支付宝/微信等）
       │
       ▼
  支付回调验签 → 订单 PAID
       │
       ▼
  余额充值或订阅履约 → 订单 RECHARGING
       │
       ├─ 成功 → 订单 COMPLETED
       └─ 失败 → 订单 FAILED（管理员可重试）
```

### 订单状态说明

| 状态 | 说明 |
|------|------|
| `PENDING` | 待支付，等待用户完成支付 |
| `PAID` | 已支付，等待充值到账 |
| `RECHARGING` | 已确认支付，余额或订阅履约进行中 |
| `COMPLETED` | 已完成，余额已到账 |
| `EXPIRED` | 已过期，超时未支付 |
| `CANCELLED` | 已取消，用户主动取消 |
| `FAILED` | 充值失败，可管理员重试 |
| `REFUND_REQUESTED` | 已申请退款 |
| `REFUNDING` | 退款处理中 |
| `REFUNDED` | 已退款 |

### 超时处理

- 订单超时后，后台任务会先查询上游支付状态再标记过期
- 如果用户实际已支付但回调延迟，系统会通过查询补单
- 后台任务每 60 秒执行一次超时检查

### 回调状态与履约状态

- provider 的已到账通知允许使用 `success` 或 `paid` 两种状态值；其他通知状态只确认接收，不触发订单履约。
- `PAID` 只表示已通过 provider 验签并完成金额和订单校验，不表示余额或订阅权益已经入账。
- 履约失败会进入 `FAILED`，管理员可以从 **支付订单** 页面重试；重试复用原支付订单和充值码，不重新创建收款订单。
- 重复回调和重复重试必须保持幂等，不能重复增加余额、延长订阅或发送多次权益。

## 链动小铺销售渠道

链动小铺当前作为外部固定商品销售渠道使用，不是 Sub2API 原生支付服务商：

1. 管理员从 `/admin/tools/ldxp` 配置商品 `goods_id`、售价、明确的余额入账额度、目标库存和启停状态。商品名称只作识别，不能推断余额额度；未映射商品和非余额商品不补货。
2. 针对固定库存基线，Sub2API 按 `新增量 = max(0, target_stock - current_unsold_stock)` 生成余额兑换码并上传到对应链动小铺商品。默认目标库存为 50,000，单段最多上传 1,000 条；预览不会生成卡密或修改远端库存。
3. 兑换码恰为 20 位，且每条同时包含数字、小写英文和大写英文。卡密由 Sub2API 管理并与批次关联，链动小铺负责销售、付款和发码，用户在 Sub2API 的兑换页面使用兑换码。
4. Sub2API 的 `RedeemService` 是唯一权益账本；链动小铺的冻结、解冻、提现和结算不改变本地支付订单状态。

补货管理接口均位于 `/api/v1/admin/tools/ldxp`，需要管理员认证、审计、专用 LDXP 限流和合规门禁：

- `GET /installation`、`POST /installation`：读取或从固定本地资产安装/修复经 SHA-256 校验的工具运行时
- `GET /status`、`PUT /config`、`POST /config/test`、`GET /goods`：读取状态、更新加密配置、只读连接检测和读取固定 `is_proxy=0` 商品
- `POST /jobs/preview`、`POST /jobs/run`：计算只读计划或创建持久化后台任务
- `GET /jobs/:id`、`POST /jobs/:id/resume`、`GET /jobs/:id/export`：读取、恢复合格失败任务或导出已完整确认上传的任务附件

远端上传结果不明时，任务会进入 `needs_reconciliation`。这不是可重试提示，而是停止条件：页面、CLI 和自动流程都不能直接再次上传，必须由技术人员先核对批次和分段证据。库存差额不是完整上传的充分证据。

独立 CLI 位于 `tools/ldxp-toolkit`，必须显式提供受保护的配置文件，例如 `ldxp-toolkit --config /secure/path/ldxp.json restock preview`。它支持 `doctor`、`goods list`、`config validate`、`restock preview`、`restock run`、`jobs status`、`jobs resume` 和 `export`，并经同一管理员任务 API 执行持久化任务。

没有正式的链动小铺服务端商户 API、签名回调、退款和对账协议前，不得把它加入支付宝/微信原生收银台或声明为 Sub2API 收款 provider。
