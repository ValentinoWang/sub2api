Claude Code 使用经验 / ERR-005

中转站已有新模型，为什么 Claude Code 看不到？

适用：自定义 Anthropic 兼容网关 · 更新：2026-09-13

01

问题说明

中转站已经提供最新模型，但 Claude Code 的 /model 仍只显示内置模型。下面以 Fable 5.1（模型 ID：claude-fable-5-1）为例说明。

模型 ID 被客户端接受、网关目录列出模型、列表可见和实际请求成功，是四个不同结果。目录有模型，不代表客户端已经主动读取该目录。

02

解决方案

  1. 确认实际网关的 /v1/models 向自己的凭证返回 claude-fable-5-1。
  2. 在用户级 settings.json 的 env 中加入 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1，其他地址、认证和设置保持不变。
  3. 关闭旧会话，重新启动 Claude Code，再打开 /model 确认 Fable 5.1 出现并可选。

03

原因、验证与注意事项

为什么网关有模型，列表却没有？

Claude Code 默认可能只显示自己的内置模型目录。启用网关模型发现后，客户端才会读取自定义接入地址提供的模型列表。旧会话不一定热加载用户级环境设置，因此修改后要用新会话验证。

怎样确认已经生效？

  • 网关目录包含目标模型，只证明该 ID 已公布。
  • /model 显示并选中 Fable 5.1，证明发现与选择状态正确。
  • 只有实际发送并完成一次请求，才能证明生成链路可用。

目录、列表和选择验证不需要产生模型请求费用。没有明确授权时，停在“可见并可选”，不要写成“请求成功”。
