# 模型目录显示规则

目录同步与选择器显示是两件事。同步脚本保留上游全部模型和能力字段；只有显示规则会改变 `visibility`，不会删除模型、改路由、扩充上下文或合并推理选项。

当前网关目录没有公开可靠的别名映射字段，脚本不会按相似名称、相同能力或日期后缀推断等价模型。默认保持最新上游显示状态；旧输出文件不是用户偏好的来源。

## 配置一次，后续自动读取

输出为 `catalog.json` 时，将规则放在同目录的 `catalog.rules.json`。脚本自动读取，不需要每次增加参数。也可用 `--rules /absolute/path/rules.json` 指定其他文件。规则示例：

```json
{
  "version": 1,
  "provider": "your-provider",
  "endpoint": "https://gateway.example/v1/models",
  "aliases": {
    "friendly-alias": "canonical-model"
  },
  "visibility": {
    "another-model": "hide"
  }
}
```

`provider` 必须对应本机实际配置，`endpoint` 必须是本次请求模型目录的完整地址，不带 `client_version` 查询参数。它用于防止换入口后套用错误规则；不是脚本下载地址，也不含凭证。不同 provider 或路径需要分别配置。

`aliases` 是经过站点说明或明确路由映射核实的“别名 → 完整型号”，不能仅因为显示名称相近就登记。如果两个名字的推理选项、价格或访问范围不同，需先判断自己是否仍需要分别选择；隐藏别名不会把它的能力合并进完整型号。

## 显示优先级与恢复

- 每次以最新上游目录为基础，应用本地 `visibility` 的 `list` 或 `hide`。
- 再处理明确别名。最终完整型号存在且可见时，隐藏别名；完整型号缺失或隐藏时保留别名的上游显示状态。
- 别名链会解析到最终型号，循环与自引用会报错。显式 `visibility` 优先于别名隐藏；可将某个别名设为 `list`，单独保留它。
- 缺失模型不会被脚本创建；输出 `picker_decisions` 说明未应用规则的原因。未知规则字段、格式错误、入口不匹配均停止，不替换旧目录。
- 删除规则条目后，下次同步恢复该条目的上游显示状态。删除规则文件或使用 `--ignore-rules` 可整体恢复上游显示状态；忽略规则不删除规则文件。

规则与输出文件分开保存，不会将一次自动隐藏变成永久偏好。更新模型、别名关系或切换入口时，只需改规则文件，无需修改 Python 脚本。

## 核验

先运行脚本核对 `rules_path`、`hidden_models` 和 `picker_decisions`。候选目录经实际 Codex 加载检查后才替换旧文件，检查包含目标窗口、模型 ID 集合和全部条目的显示状态。`upstream_sha256` 对应原始响应，`sha256` 对应应用规则后的文件，二者不同可以是预期结果。

重新加载客户端目录后核对选择器；目录验证不代表真实生成或最大上下文已经验收。备份只恢复目录文件，规则回滚需要单独修改或恢复规则文件。
